# 群语音手记 · AstrBot Voice Journal

独立的 AstrBot 插件：在 A 本机采集，或由 B 电脑分别采集群聊播放和麦克风声音，传给 A 离线转写并区分说话人，试听审核 QQ 身份，用已有模型提供商生成通话复盘。

当前版本 **不会自动发起、加入或接听 QQ 群通话**。请先在 QQ 中发起／加入语音，再点击采集器的开始按钮。QQ 通话控制留有独立接口，当前不把静音当成“所有人退出”。

## A、B 两台电脑使用（v0.2.0）

**A 运行 AstrBot、NapCat 和模型；B 只用自己的 QQ 参加语音。机器人账号不必加入通话，也不用在 B 登录。**

1. A、B 安装 [Tailscale](https://tailscale.com/docs/install/windows)，登录同一私有网络。记下 A 的 `100.x.x.x` 地址。只需这两台电脑互通，不需要路由器端口映射或 Tailscale Funnel。
2. A 的插件配置启用「B 端录音接收」，重启 AstrBot。在 A 打开语音手记面板，在「B 端录音接入」填写 `https://A的Tailscale地址:7845`，导出连接文件。如果 Windows 防火墙拦截，可在 A 的管理员 PowerShell 运行 `tools/allow_tailscale_receiver.ps1`，它只允许来自 Tailscale 地址范围的 7845/TCP 入站连接。
3. B 下载 [Windows 采集器](https://github.com/Quin520/AstrBot-QQ-Voice-Journal/releases/latest/download/VoiceJournal-B-Windows-x64.zip)，解压整个压缩包并运行 `VoiceJournalB.exe`。导入 A 的连接文件，点击「测试连接」，选择与 QQ 一致的播放设备和麦克风。B 不需要安装 AstrBot、Python、Codex 或语音模型。
4. B 加入 QQ 群语音，确认参与者知悉记录后点击「开始录音并自动同步」。使用耳机，避免播放声音重新进入麦克风。停止时封口并补传最后一段，在 A 的同一语音记录里审核两条音轨对应的声音组。

每段最长 10 分钟，按 A 的分段配置执行；两条音轨分别转写，按相对时间排列。麦克风轨道不会自动认定为管理者，身份仍需人工审核。模型推理和声纹样本都在 A；B 保存录音副本和待上传清单，网络恢复或下次启动后自动补传，成功后本地副本也保留，需自行清理。不要在录音或补传时移动本地录音文件。

插件配置里的「B 端接收监听地址」是 **A 本机绑定的 IP**，通常保留 `0.0.0.0` 即可；面板里的连接地址才是交给 B 的 `https://A地址:7845`。v0.2.1 起也兼容在监听字段粘贴完整 HTTPS 网址和首尾空格，网址端口必须与单独的上传端口设置一致。

传输使用 TLS 和配对文件中的证书指纹，凭据发送前先核对 A 的证书。独立上传口令不能访问审核、QQ 控制或其他本机文件。A 面板可以撤销旧连接文件，撤销后 B 重新导入新文件继续补传。连接文件含私密口令，勿上传仓库。A 更换证书或换成另一台服务器时，B 不会自动把旧录音交给新服务器。

如 B 已不可用，可在 A 的该条记录中点击「结束 B 端接收」，之后可删除记录；这不会远程停止 B 的麦克风，但会阻止该条录音后续补传。A 删除的记录不会因 B 重试而重新出现。B 界面会显示未传完的本地副本仍被保留。

**跨网络需要 A、B 同时在线且 Tailscale 已连接。** 当前提供的是分段自动上传，不是实时通话字幕。审核面板仍只在 A 的 `127.0.0.1:7844`，不会因为启用上传接口而对 B 开放管理员功能。更详细的 B 端说明和源码运行方式见 [client/README.md](client/README.md)。

## 使用方式

1. 在 AstrBot 插件管理中选择从链接安装，填入 `https://github.com/Quin520/AstrBot-QQ-Voice-Journal`；也可将本目录作为 `astrbot_plugin_voice_journal` 放入 AstrBot 的 `data/plugins/`。安装后填写目标群、唯一管理者 QQ、QQ 平台实例 ID 和总结提供商 ID。
2. 安装独立语音环境（推荐 Python 3.12）：

   ```powershell
   python setup_runtime.py C:\BotRuntime\VoiceJournal
   ```

   将脚本输出的 `engine_python` 和 `engine_cache` 填入插件配置。Torch、FunASR 和采集依赖均安装在独立环境中；不要装入 AstrBot 主环境。首轮模型下载需要数 GB 磁盘空间。默认 CPU、2 个线程，处理结束后退出模型进程。
3. 重载插件或重启 AstrBot。管理者私聊 `/语音手记` 获取本机面板入口，默认 `http://127.0.0.1:7844/`。入口含管理口令，不要转发。也可从本插件数据目录的 `panel-token.txt` 读取口令，在页面输入。
4. 先在 QQ 加入群语音，刷新并选择 QQ 正在使用的输出设备。确认参与者知悉记录，再点「开始采集」；默认每 10 分钟处理一段，停止时处理余下音频，最长 120 分钟自动停录。
5. 每个声音组可以试听最多 3 段代表音频、查看转写、同步群成员、选择或手填 QQ 和昵称，点击「确认是此人」。不确定或混合人声可排除，认错可更正／撤销。
6. 每段转写完成可自动生成面板复盘。身份审核后，旧复盘会标记过期，点击「重新生成复盘」使用新身份。可导出文本；删除记录也会删除来源于该记录的声纹样本。

没有方便的回环设备时，可以导入 WAV、MP3、M4A、FLAC、OGG、AAC、WEBM，最大 256 MB。群员同步失败时仍支持手填 QQ 和昵称。

## 审核怎样让识别改善

- 使用 SenseVoiceSmall、FSMN-VAD、标点模型及 CAM++。声纹是 192 维特征，不是给聊天模型微调，也不根据文字猜谁在说话。
- **只有人工确认且质量合格的声音组**才加入本插件声纹库。有效样本至少 5 秒；组内特征差异过大时，认定只用于当次文字归属，不作为学习样本。
- 后续录音与同群、同模型版本的已确认样本比较，展示候选和余弦相似度。默认参考阈值 0.72、前两名差值 0.10，均可配置；这些值需要用真实群聊校准，不是准确率。
- 模型猜测永远不会自动成为训练样本，也不会直接成为已确认身份。每次仍可人工检查，避免错误自我强化。
- 可以逐步积累同一个人在不同麦克风、音量和状态下的样本，每人每个模型版本最多选取最近 20 个有效示例参与匹配。准确率不保证随数量单调提高，错误标注和多人混音会降低效果。
- 更正、撤销和「忘记」会立即改变可用样本。原始审核变更保留在本插件的私有 SQLite 中，直到删除对应记录。
- 未审核声音组在复盘中保持匿名；同一人的不同匿名组不会被总结模型擅自合并。审核时可以将多个组认定给同一 QQ。

## 当前边界

- 采集的是所选 Windows 输出设备的声音，**不局限于 QQ 进程**。请使用 QQ 专用输出设备，或避免同时播放其他声音。A 本机旧入口不额外打开麦克风；B 端会单独采集所选麦克风。
- **仅在手机 QQ 加入语音，电脑上的插件录不到手机音频**。需要在这台 Windows 电脑上参与通话并播放声音，或先把手机音频送到所选输出设备；登录同一个 QQ 账号不会自动转接通话音频。
- 是按分段处理的通话记录，不是实时双向语音聊天。没有经验证的 QQ 群通话参与者事件，所以默认由人停止或到达时长上限停止。
- 同时抢话、音乐、人声特效和连续无停顿的换人可能分组不准确。请试听审核；不能把说话人数或成员归属当成已知事实。
- 默认只在面板展示复盘，**不会自动发到 QQ 群，不会改好感度、人物配置或长期记忆**。总结文本会交给你选择的 AstrBot 提供商；音频和声纹留在本机。
- 如果模型处理失败，页面保留分段错误和「重试」入口。停用插件会停止采集、终止本插件模型进程；已完成的录音和审核结果保留。

## 不耦合的结构

| 模块 | 责任 |
|---|---|
| `main.py` | 只通过 AstrBot 的 `llm_generate`、平台客户端和插件数据目录接口接入 |
| `service.py` | 采集生命周期、分段队列、复盘任务；总结、成员列表、引擎通过参数注入 |
| `capture_worker.py` | 独立进程使用 WASAPI 回环采集，通过标准输入停止、标准输出报告分段 |
| `worker.py` / `engine.py` | 独立语音环境，模型推理通过请求／结果 JSON 传递 |
| `store.py` / `matching.py` | 本插件数据库、可撤销审核、按群和模型隔离的候选匹配 |
| `web.py` / `ui/` | 独立本机审核面板、口令认证、音频试听 |
| `call_control.py` | 预留 `CallControl` 接口：能力查询、发起通话、参与者列表；当前为手动适配器 |
| `remote.py` / `remote_store.py` / `remote_tls.py` | 独立上传入口、持久化接收回执、TLS 配对；重传不重复生成记录 |
| `client/` | B 端轻量 GUI、双音轨采集、持久化补传队列；不导入 AstrBot 或模型 |

无需修改 Codex 桥接或其他插件源码，不读取它们的数据库。总结提供商可选 `local_codex` 或其他 AstrBot 已配置的聊天模型。停用本插件不会卸载共享提供商。

扩展真正的一键 QQ 通话时，实现 `CallControl` 并注入 `JournalService`。只有适配器返回可靠参与者状态后，才能实现“其他人全部离开”的触发器；返回 `None` 表示未知，不能当作空列表。

## 数据与访问

数据统一保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_voice_journal/`，包括录音、试听片段、声纹、转写、审核和本机管理口令。源码包不包含这些文件，也不要将它们提交到公共仓库。

面板仅监听 `127.0.0.1`，API 必须有管理口令；拒绝非本机 Host 和跨站 Origin。QQ 命令只向配置的管理者私聊提供入口，群聊和其他账号无法启动采集、认定声音或访问本机文件。可选的 7845/TCP 接收服务只接收本机、局域网或 Tailscale 来源的带凭据请求，且只提供上传接口，不提供管理面板。卸载插件保留数据；不再需要时先导出，再删除该插件私有数据目录。
